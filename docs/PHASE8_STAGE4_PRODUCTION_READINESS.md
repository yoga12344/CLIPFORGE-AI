## 2. Architecture & Operational Guidelines

### 2.1 Pipeline Flow & Data Lifecycle
```
[Video File]
     │
     ├──> [FFmpeg PTS Audio Extractor] ──> [Silero VAD] ──────────────┐
     │                                                                │
     └──> [Decord/OpenCV Video Decoder]                               │
                 │ (sampled at 4 FPS keyframes)                       │
                 ▼                                                    │
          [YuNet Face Detector & Tracker]                             │
                 │                                                    │
                 ▼ (linear bounding-box interpolation to 25 FPS)      │
          [Face Mesh Landmark Detector] (Lip Contour & Motion)        │
                 │                                                    │
                 ▼                                                    │
          [Light-ASD ONNX Inference] (Short-term Audio-Visual)        │
                 │                                                    │
                 └───────────────► [AVFusionEngine] ◄─────────────────┘
                                         │
                                         ▼ (Dual Hysteresis: on=0.65, off=0.35)
                              [Active Speaker Intervals]
                                         │
                                         ▼ [SpeakerFaceAssociator] (Hungarian Matching)
                              [Speaker-Face Association Map]
                                         │
                                         ├──> [SQLite Database Persistence]
                                         └──> [Phase 6 Auto-Reframing Service]
```

### 2.2 Threading & Resource Configuration
To guarantee system responsiveness on host machines with lower thread counts, ONNX Runtime sessions are explicitly configured:
- `intra_op_num_threads`: **4** (balanced between multi-core parallelism and CPU saturation)
- `inter_op_num_threads`: **1**
- `execution_mode`: `ExecutionMode.ORT_SEQUENTIAL`
- `graph_optimization_level`: `GraphOptimizationLevel.ORT_ENABLE_ALL`

### 2.3 Chunked Processing Model
- Inference is batched into **25-frame chunks** (1.00 second of video at 25 FPS).
- Video frames are streamed via Python generators; frames are never cached globally.
- Immediate garbage collection of extracted face crops ensures flat memory usage regardless of video duration (10 seconds or 2 hours).

## 3. Downstream Integration: Phase 6 Auto-Reframing

The active speaker intervals generated by `ActiveSpeakerService` connect directly to the Phase 6 `ReframeEngine`:
- **Dynamic Framing**: When an active speaker interval is detected, `ReframeEngine` centers the 9:16 vertical crop window on that speaker's face bounding box.
- **Smooth Transition**: A Gaussian motion filter ($1.2$s transition window) prevents jarring camera jump-cuts during rapid speaker dialogue exchanges.
- **Off-Screen Narration Handling**: When speech is detected but no face is active (`face_track_id=None`), the reframing engine smoothly holds a wide framing or centers on the scene centroid.

## 4. Maintenance & Support Procedures

### Model Artifact Integrity Check
If model files are suspected of corruption, run:
```powershell
python -c "from app.ai.vision.light_asd import LightASDDetector; d = LightASDDetector(); print('Light-ASD OK'); from app.ai.vision.landmark_detector import LandmarkDetector; l = LandmarkDetector(); print('Landmarks OK')"
```

### Manual Overrides via REST API
To lock a speaker identity to a specific face track:
```http
POST /api/active-speaker/{analysis_id}/override
Content-Type: application/json

{
  "speaker_id": "SPEAKER_00",
  "face_track_id": 1,
  "lock_association": true
}
```
This sets `is_manual_override = 1` in the database, preventing future automated clustering or association runs from overwriting user intent.
