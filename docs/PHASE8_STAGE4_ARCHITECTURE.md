# CLIPFORGE AI — PHASE 8, STAGE 4
# AUDIO-VISUAL ACTIVE SPEAKER DETECTION ARCHITECTURE

## 1. System Overview & Executive Summary

Phase 8, Stage 4 introduces **Audio-Visual Active Speaker Detection (AV-ASD)** and **Speaker-to-Face Identity Association** into ClipForge AI.

ClipForge AI already possesses:
1. **Phase 6 Computer Vision**: Real-time YuNet face detection, spatial-temporal face tracking (`FaceTrack`), framing selection (`SubjectSelector`), and smooth crop generation (`ReframeEngine`).
2. **Phase 8 Stage 2 Audio Intelligence**: Canonical 16 kHz mono PCM extraction (`AudioPreprocessor`) and local Silero VAD speech segmentation (`SpeechInterval`).
3. **Phase 8 Stage 3 Speaker Diarization**: 3D-Speaker CAM++ ONNX embeddings, cosine affinity spectral clustering, and persistent speaker turns (`Speaker`, `SpeakerTurn`).

Stage 4 connects these two independent streams into a unified multimodal intelligence engine. The primary objectives are:
- **Active Speaker Detection (Concept A)**: At any given millisecond $t$, determine which visible face track(s) $T_j$ are vocalizing.
- **Speaker-Face Association (Concept B)**: Over the entire clip/video duration, determine which acoustic identity $S_i$ corresponds to visual face track $T_j$.
- **Smart Reframing Enhancement**: Automatically focus and reframe portrait crops on the current active speaker with cinema-grade smoothness, headroom preservation, and graceful handling of off-screen speakers and multi-speaker dialogue.

## 2. Audio-Visual Synchronization Architecture

### 2.1 The Common Source-Relative Timeline
Accurate active speaker detection requires sub-frame audio-visual temporal alignment (typically within $\pm 20$ ms).
- **Source Video Timeline**: Defined strictly by Container Presentation Timestamps (PTS) extracted via FFprobe/PyAV/OpenCV. Naive frame indexing ($t = \frac{\text{frame\_idx}}{\text{nominal\_fps}}$) is strictly prohibited because Variable Frame Rate (VFR) recordings from mobile phones, Zoom, OBS, and screen recorders suffer from cumulative timestamp drift of up to hundreds of milliseconds.
- **Source Audio Timeline**: Sourced directly from the canonical 16 kHz mono WAV generated by `AudioPreprocessor`. During extraction, FFmpeg enforces zero-PTS synchronization:
  ```bash
  -af "aresample=async=1:first_pts=0"
  ```
  Every audio sample $n$ maps directly to timestamp $t = \frac{n}{16000.0}$ seconds from the exact beginning of video PTS 0.

### 2.2 Synchronized Audio-Visual Window Builder
ASD models require evaluating a short temporal context (typically 0.4s to 0.6s) around each video frame:
1. **Video Temporal Stride**: Face tracks are sampled at target rate (e.g. 25 FPS or source frame timestamps). For each video frame at timestamp $t_k$, face bounding boxes are cropped and scaled to model resolution (e.g. $112 \times 112$ or $96 \times 96$).
2. **Audio Window Alignment**: For video frame timestamp $t_k$, the corresponding audio segment spans:
   $$[t_k - \frac{W}{2}, t_k + \frac{W}{2}]$$
   where $W = 0.4\text{s}$ (6,400 samples at 16 kHz) or $W = 0.6\text{s}$ (9,600 samples).
3. **Boundary Padding**: If $t_k - W/2 < 0$, the audio is symmetrically zero-padded or reflection-padded at the start. If $t_k + W/2 > T_{\text{duration}}$, the trailing samples are padded accordingly.
4. **Zero Re-Extraction**: Audio slices are read directly from memory-mapped PCM or pre-buffered 16 kHz float32 arrays in RAM, incurring zero disk I/O or FFmpeg process overhead.

```mermaid
flowchart LR
    Video[Source Video Container] -->|Container PTS| VideoFrames[Video Frames & Face Bounding Boxes]
    Video -->|FFmpeg async=1:first_pts=0| Audio16k[Canonical 16kHz Mono PCM]
    
    VideoFrames --> SyncEngine[AV Synchronizer Engine]
    Audio16k --> SyncEngine
    
    SyncEngine -->|Crop Face + [t-0.2s, t+0.2s] Audio| AVWindows[Synchronized AV Windows]

```

## 3. Clear Distinction: Concept A vs Concept B

To maintain architectural rigor, the system strictly separates instantaneous detection from global identity association:

```
+---------------------------------------------------------------------------------------+
|                                    CONCEPT A                                          |
|                         ACTIVE SPEAKER DETECTION (ASD)                                |
|                                                                                       |
| Question: "Is Face Track #1 moving their lips and speaking right now at t = 14.2s?"   |
| Scope:    Instantaneous / Frame-level (local temporal window 0.4s - 1.0s).            |
| Output:   ActiveSpeakerInterval records: (video_id, face_track_id, start_time,        |
|           end_time, confidence, speech_intensity).                                    |
+---------------------------------------------------------------------------------------+
                                           |
                                           v
+---------------------------------------------------------------------------------------+
|                                    CONCEPT B                                          |
|                     SPEAKER-TO-FACE IDENTITY ASSOCIATION                              |
|                                                                                       |
| Question: "Is Diarization Speaker 'SPEAKER_00' actually Face Track #1 or #2?"        |
| Scope:    Global / Video-level (aggregated over all speech turns & face appearances). |
| Output:   SpeakerFaceAssociation records: (video_id, speaker_id, face_track_id,       |
|           confidence, overlap_duration, manual_override).                             |
+---------------------------------------------------------------------------------------+
```

### Why Separation is Mandatory:
1. **Handling Off-Screen Speakers**: A person speaking may be off-camera (e.g. interviewer behind the camera, voice-over, narrator). Concept A detects that visible faces are NOT speaking. Concept B assigns the acoustic speaker ID to an off-screen entity rather than falsely binding it to a silent visible face.
2. **Handling Occluded / Lost Faces**: When an active speaker turns away or steps out of frame, Concept A flags the face as absent/inactive, while Concept B remembers their acoustic identity.
3. **Handling Multi-Speaker Cross-Talk**: Two visible faces may speak simultaneously. Concept A identifies both as active. Concept B pairs each acoustic channel/embedding with their corresponding face track.

## 4. Multi-Evidence Audio-Visual Fusion Engine

The fusion engine synthesizes four distinct evidence streams to produce reliable active speaker confidence without false triggers from chewing, smiling, or background speech.

```mermaid
flowchart TD
    subgraph Stream 1: Acoustic Activity
        VAD[Silero VAD v4 Engine] -->|Binary Speech Intervals| AcState[Acoustic Speech Gate]
        Diar[CAM++ Diarization Engine] -->|Speaker Turns S_i| SpkTurns[Speaker Identity Timeline]
    end

    subgraph Stream 2: Visual Dynamics
        FaceCrop[Face Track Crops] --> MeshONNX[MediaPipe Face Mesh ONNX]
        MeshONNX -->|Upper/Lower Lip Dist| MAR[Mouth Aspect Ratio Velocity dMAR/dt]
    end

    subgraph Stream 3: Audio-Visual Correlation
        AVWin[AV Synchronized Windows] --> LightASD[Light-ASD ONNX]
        LightASD -->|Raw AV Score [-inf, +inf]| ASDProb[Sigmoid ASD Probability P_asd]
    end

    AcState --> FusionEngine[Multimodal AV Fusion Engine]
    SpkTurns --> FusionEngine
    MAR --> FusionEngine
    ASDProb --> FusionEngine

    FusionEngine --> Hysteresis[Temporal Hysteresis & Filtering]
    Hysteresis --> ActSpkInt[ActiveSpeakerIntervals (Concept A)]
    Hysteresis --> Association[SpeakerFaceAssociation (Concept B)]
```

### 4.1 Fusion Scoring Formulation

For face track $j$ at time $t$:

1. **Acoustic Speech Gate ($G_{\text{vad}}(t)$)**:
   $$G_{\text{vad}}(t) = \begin{cases} 1.0 & \text{if } t \in \bigcup \text{SpeechInterval} \\ 0.0 & \text{otherwise} \end{cases}$$
   If no acoustic speech is occurring anywhere in the audio, no visible face can be classified as an active speaker (eliminates chewing, yawning, and smiling false positives).

2. **Visual Mouth Dynamics ($M_{\text{lip}}(j, t)$)**:
   Using MediaPipe Face Mesh ONNX 3D lip landmarks (inner upper lip 13, inner lower lip 14, left corner 61, right corner 291):
   $$\text{MAR}(j, t) = \frac{\|p_{13}(t) - p_{14}(t)\|_2}{\|p_{61}(t) - p_{291}(t)\|_2}$$
   Visual dynamics score is computed from the short-term variance and velocity of MAR:
   $$V_{\text{mar}}(j, t) = \text{std}_{u \in [t-0.2, t+0.2]}(\text{MAR}(j, u))$$
   Normalized to $[0, 1]$ via a sigmoid transfer function:
   $$M_{\text{lip}}(j, t) = \frac{1}{1 + e^{-k_m (V_{\text{mar}} - \tau_m)}}$$

3. **Audio-Visual Cross-Modal Score ($P_{\text{asd}}(j, t)$)**:
   Output of Light-ASD / LR-ASD ONNX:
   $$P_{\text{asd}}(j, t) = \sigma(\text{LightASD}(\text{Crop}_j(t), \text{Audio}(t)))$$

4. **Instantaneous Composite Score ($S(j, t)$)**:
   $$S(j, t) = G_{\text{vad}}(t) \cdot \left[ \alpha P_{\text{asd}}(j, t) + (1 - \alpha) M_{\text{lip}}(j, t) \right]$$
   where default $\alpha = 0.70$.
   If Light-ASD is run in visual-fallback mode (or low-power mode), $\alpha = 0.0$ and $S(j, t) = G_{\text{vad}}(t) \cdot M_{\text{lip}}(j, t)$.

5. **Temporal Hysteresis & Smoothing**:
   To prevent erratic flickering between speakers during natural speech pauses:
   - **Onset Threshold** ($\tau_{\text{on}} = 0.65$): Face $j$ becomes ACTIVE when $S(j, t) \ge \tau_{\text{on}}$ for at least 3 consecutive frames (120 ms).
   - **Offset Threshold** ($\tau_{\text{off}} = 0.35$): Face $j$ remains ACTIVE until $S(j, t) < \tau_{\text{off}}$ for at least 6 consecutive frames (240 ms, bridging stop-consonants and brief pauses).
   - **Minimum Active Duration**: 300 ms.
   - **Minimum Inactive Gap**: 200 ms.

### 4.2 Four Mutually Exclusive States per Frame
For each frame, the engine categorizes visible and audible entities into:
1. `ACTIVE_SPEAKER`: Face track is visible and composite active score $S(j, t) \ge \tau_{\text{on}}$.
2. `SILENT_LISTENER`: Face track is visible, but $S(j, t) < \tau_{\text{off}}$ (listening, reacting, nodding).
3. `OFF_SCREEN_SPEAKER`: Audio VAD indicates speech ($G_{\text{vad}} = 1$), but all visible faces have $S(j, t) < \tau_{\text{off}}$ or no faces exist.
4. `AMBIGUOUS_SPEAKER`: Multiple visible faces exhibit high visual motion during cross-talk or poor video resolution, confidence margin $< 0.15$. The system explicitly flags this as ambiguous rather than guessing.

## 5. Speaker-to-Face Identity Association (Concept B)

Global association links acoustic diarization cluster $S_i$ with visual face track $T_j$.

### 5.1 Temporal Co-Occurrence Matrix
Let $T_{\text{spk}}(S_i)$ be the set of time intervals where Diarization speaker $S_i$ is vocalizing.
Let $T_{\text{act}}(T_j)$ be the set of time intervals where Face Track $T_j$ is classified as `ACTIVE_SPEAKER`.

The co-occurrence overlap duration is:
$$O(S_i, T_j) = \int_{0}^{T} \mathbb{I}(t \in T_{\text{spk}}(S_i) \land t \in T_{\text{act}}(T_j)) \, dt$$

The normalized association confidence is computed using the Jaccard / Overlap coefficient:
$$C(S_i, T_j) = \frac{O(S_i, T_j)}{\int_{0}^{T} \mathbb{I}(t \in T_{\text{spk}}(S_i) \lor t \in T_{\text{act}}(T_j)) \, dt}$$

### 5.2 Association Algorithm
1. Compute the affinity matrix $C_{ij} = C(S_i, T_j)$ across all speakers $i \in \{1 \dots N_s\}$ and face tracks $j \in \{1 \dots N_f\}$.
2. Solve maximum weight bipartite matching via the Hungarian Algorithm (`scipy.optimize.linear_sum_assignment`).
3. **Thresholding**: If the highest association confidence for speaker $S_i$ is below $\tau_{\text{assoc}} = 0.30$, mark $S_i$ as `OFF_SCREEN` (unassociated).
4. **Manual Override Preservation**: If a user manually assigns a speaker to a face in the UI, that association is marked `is_manual = True` and is permanently protected from automated re-clustering.

## 6. Smart Reframing Integration

### 6.1 Reframing Strategy: `active_speaker`
In Phase 6, `SubjectSelector` supports `face_tracking`, `single_subject`, and `group_shot`.
Stage 4 extends `SubjectSelector` and `ReframeEngine` with the `active_speaker` strategy:

```
                          Target Selection in Frame t
                                       │
                ┌──────────────────────┴──────────────────────┐
                ▼                                             ▼
       Active Speaker Found?                         No Active Speaker?
                │                                             │
      ┌─────────┴─────────┐                         ┌─────────┴─────────┐
      ▼                   ▼                         ▼                   ▼
Single Active        Multi Active             Speech Occurring?     Total Silence?
Speaker Visible      Cross-Talk?                 (Off-Screen)             │
      │                   │                         │                     │
Frame Active Face    Compute Bounding         Maintain Last Active        Zoom Out to
Preserve Headroom    Box Union of Both        Speaker Crop with Slow      Wide/Group Shot
& Eye-Line Level     Active Faces             Decay (3.0s Holdout)        or Centered
```

### 6.2 Key Reframing Rules:
1. **Headroom & Eye-Level Rule**: The crop window must position the active speaker's eyes at approximately the upper $1/3$ line of the vertical 9:16 frame.
2. **Exponential Moving Average (EMA) Panning**: Smooth camera repositioning using the existing double-filtered EMA in `ReframeEngine`, preventing abrupt jump cuts.
3. **Switch Delay Hysteresis**: When Speaker B starts speaking while Speaker A stops, the camera does not instantly swing. It applies a 300 ms hold threshold. If Speaker B speaks for $> 300$ ms, camera pans smoothly at maximum velocity $v_{\text{max}} = 0.08$ frame widths/second.
4. **Off-Screen Speaker Holdout**: If an off-screen speaker speaks, the camera holds on the last active speaker for 3 seconds before slowly pulling out to a group shot, replicating professional television broadcast camera operator behavior.

## 7. Database Schema Extensions

To store active speaker and association metadata persistently and support user overrides:

### 7.1 New Table: `active_speaker_intervals`
```sql
CREATE TABLE active_speaker_intervals (
    id VARCHAR(36) PRIMARY KEY,
    video_id VARCHAR(36) NOT NULL REFERENCES videos(id) ON DELETE CASCADE,
    face_track_id VARCHAR(36) REFERENCES face_tracks(id) ON DELETE CASCADE,
    start_time FLOAT NOT NULL,
    end_time FLOAT NOT NULL,
    confidence FLOAT NOT NULL,
    speech_intensity FLOAT,
    state VARCHAR(32) NOT NULL DEFAULT 'ACTIVE_SPEAKER', -- ACTIVE_SPEAKER, SILENT_LISTENER, AMBIGUOUS, OFF_SCREEN
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_active_speaker_video ON active_speaker_intervals(video_id, start_time);
```

### 7.2 New Table: `speaker_face_associations`
```sql
CREATE TABLE speaker_face_associations (
    id VARCHAR(36) PRIMARY KEY,
    video_id VARCHAR(36) NOT NULL REFERENCES videos(id) ON DELETE CASCADE,
    speaker_id VARCHAR(36) NOT NULL REFERENCES speakers(id) ON DELETE CASCADE,
    face_track_id VARCHAR(36) REFERENCES face_tracks(id) ON DELETE SET NULL,
    confidence FLOAT NOT NULL,
    overlap_duration FLOAT NOT NULL,
    is_manual BOOLEAN NOT NULL DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(video_id, speaker_id)
);
```

### Execution Concurrency:
- Video and Audio decoding run sequentially or decoupled through the existing persistent `JobExecutor`.
- CAM++ Diarization and Light-ASD share the same ONNX Runtime CPU execution provider, executing in staged order so total peak process memory remains well below the 16 GB system budget.
