# ClipForge AI — Local AI Transcription Engine Documentation

## Overview

The ClipForge AI Transcription Engine provides high-performance, local-first automated speech recognition (ASR) without relying on cloud services, external APIs, subscriptions, or telemetry. Built upon `faster-whisper` and `CTranslate2`, it ingests extracted 16kHz mono WAV audio generated by the video engine, accurately detects speech boundaries with Silero VAD, produces word-level timestamps, and streams live progress to the desktop frontend over WebSockets.

---

## 1. Architecture & Component Hierarchy

The transcription subsystem is organized cleanly within `backend/app/ai/` and integrates with existing background job workers and SQLite persistence:

```
backend/app/
├── ai/
│   ├── model_registry.py          # Metadata, URLs, sizes, and file manifests for Whisper models
│   ├── device_detector.py         # Hardware capability detection with cuBLAS validation & CPU fallback
│   ├── transcription_config.py    # Pydantic schemas for transcription configuration
│   ├── model_manager.py           # On-demand model download, disk verification, and removal
│   ├── transcription_validator.py # Audio readability, duration, and silence/zero-speech checks
│   └── transcription_engine.py    # Sequential inference worker, progress streamer, and fallback handler
├── services/
│   ├── transcript_repository.py   # SQLite CRUD operations, segment text updates, fulltext rebuild
│   └── transcription_service.py   # Pipeline coordinator (audio extraction -> validation -> transcription -> DB)
├── api/routes/
│   ├── transcription.py           # Hardware capabilities, model catalog, and download triggers
│   └── transcripts.py             # Transcript retrieval, segment editing, and transcription jobs
└── workers/
    └── job_executor.py            # Background worker task 'transcribe_video'
```

## 2. Supported Whisper Models

ClipForge AI supports 4 standardized quantized models hosted on HuggingFace by Systran. Each model is pinned to an exact SHA256/file manifest to prevent corrupted downloads.

| Model | Memory / VRAM | Parameter Count | Relative Speed | Recommended Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **tiny** | ~500 MB RAM | 39 M | ~32x real-time | Fast previews, tests, low-end hardware |
| **base** | ~750 MB RAM | 74 M | ~16x real-time | General balance of speed and draft accuracy |
| **small** *(Default)* | ~1.5 GB RAM | 244 M | ~6x real-time | Recommended default for high accuracy video clipping |
| **medium** | ~3.5 GB RAM | 769 M | ~2x real-time | Highest accuracy transcription for complex audio |

### Model Storage & File Verification
Models are stored under `backend/storage/clipforge_data/models/whisper/{model_name}/`.
Before marking any model as ready, the `ModelManager` verifies that all required CTranslate2 artifacts exist on disk:
- `model.bin`
- `config.json`
- `tokenizer.json`

Download progress is tracked in real-time and broadcast through callbacks. Downloads can be cancelled cleanly without leaving corrupted partial files.

## 3. Hardware Capability Detection & Fallback Engine

Located in `backend/app/ai/device_detector.py`.

### Target Hardware Environment
- **Processor**: Intel Core i7-13620H (16 physical/logical threads)
- **GPU**: NVIDIA GeForce RTX 4060 Laptop GPU (8GB VRAM)
- **OS**: Windows 11 64-bit

### Device Resolution Strategy
1. **CUDA Detection**: CTranslate2 identifies the RTX 4060 GPU (`cuda:0`).
2. **cuBLAS Runtime Probe**: CTranslate2 requires `cublas64_12.dll` in the Windows DLL search path to execute matrix operations on CUDA. `DeviceDetector` actively attempts to load `cublas64_12.dll` via `ctypes.cdll.LoadLibrary`.
3. **Graceful Automatic Fallback**: If `cublas64_12.dll` is absent or encounters a dynamic link error:
   - Device falls back to `cpu`.
   - Compute type automatically resolves to `int8` (quantized 8-bit inference using AVX-512/AVX2).
   - CPU thread count is dynamically configured to `min(8, os.cpu_count() or 4)`.
   - The engine logs explicit diagnostics and reports `device_used="cpu (fallback)"` without interrupting or crashing the user's transcription pipeline.

## 4. Transcription Engine Lifecycle (`TranscriptionEngine`)

### 4.1. Sequential Model Execution
To prevent Out-Of-Memory (OOM) errors on 8GB VRAM / 16GB RAM hardware:
- Only **one** major inference task executes at any given time using an `asyncio.Lock`.
- Models are initialized lazily upon job start and unloaded (`del self._current_model`, `gc.collect()`) upon job completion or failure.

### 4.2. Pre-Validation & Silence Handling
`TranscriptionValidator` inspects the audio stream prior to model inference:
- Checks file presence and readability.
- Rejects audio files shorter than 0.5 seconds.
- Analyzes audio energy: if the file contains pure silence or zero speech, it returns an empty transcript with `status="completed"` rather than hanging the model or producing hallucinated loops.

### 4.3. Word-Level Timestamps & VAD
The engine enables:
- `word_timestamps=True`: Yields word-level start/end offsets and confidence scores for karaoke-style caption highlighting and precise word-level video cutting.
- `vad_filter=True`: Employs Silero VAD with `min_silence_duration_ms=500` to strip long pauses, background hum, and silence segments.
- `condition_on_previous_text=False`: Prevents Whisper from hallucinating repeating phrases across segment boundaries.

### 4.4. Streaming Progress Calculation
As `faster_whisper` yields segments sequentially, the engine calculates:
$$\text{Progress} = \min\left(95.0, \frac{\text{segment.end}}{\text{total\_duration}} \times 100\right)$$
Progress is broadcast via WebSocket to the desktop UI, giving users smooth feedback across long files.

## 5. Database Schema & Persistence

Transcripts, segments, and words are persisted in SQLite:

### `transcripts` Table
- `id`: Primary key (UUID string)
- `video_id`: Foreign key to `videos.id` (1:1 relationship)
- `language`: Detected or specified language (e.g. `'en'`)
- `language_probability`: Detection confidence float (0.0 to 1.0)
- `model_name`: Whisper model name used (e.g. `'small'`)
- `full_text`: Complete assembled transcript text
- `status`: Transcription status (`'completed'`, `'failed'`, `'processing'`)
- `task_type`: `'transcribe'` or `'translate'`
- `device_used`: Hardware used (`'cuda'`, `'cpu'`, or `'cpu (fallback)'`)
- `processing_duration_seconds`: Wall-clock processing time
- `created_at` / `updated_at`: Timestamps

### `transcript_segments` Table
- `id`: Primary key (UUID string)
- `transcript_id`: Foreign key to `transcripts.id`
- `start_time`: Start time in seconds (float)
- `end_time`: End time in seconds (float)
- `text`: Segment text
- `confidence`: Average logprob/confidence
- `words_json`: JSON-serialized array of words with individual `start`, `end`, and `probability`

## 6. REST API Endpoints

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/api/ai/capabilities` | Hardware status, CUDA/CPU detection, and active fallback details |
| `GET` | `/api/ai/models` | List all Whisper models with download status, size, and disk path |
| `POST` | `/api/ai/models/{name}/download` | Start asynchronous model download |
| `DELETE` | `/api/ai/models/{name}` | Delete downloaded model from local storage |
| `POST` | `/api/videos/{video_id}/transcribe` | Queue asynchronous `transcribe_video` background job |
| `GET` | `/api/videos/{video_id}/transcript` | Retrieve complete transcript with segments and words |
| `GET` | `/api/transcripts/{transcript_id}` | Retrieve transcript by transcript ID |
| `PATCH` | `/api/transcripts/segments/{segment_id}` | Edit segment text; automatically synchronizes parent `full_text` |

## 7. Frontend User Experience

The interactive React UI provides:
1. **Interactive Word Highlighting (`TranscriptWord`)**: Highlights current spoken word in real-time synchronized with `<VideoPlayer />` playback. Clicking any word or timestamp seeks the video immediately.
2. **Inline Segment Editing (`TranscriptSegment`)**: Allows creators to edit transcription errors directly in the interface and saves changes instantly to SQLite.
3. **Fulltext Search (`TranscriptSearch`)**: Case-insensitive text search with result highlighting, match counter, and next/previous jump navigation.
4. **Model & Language Controls (`TranscriptionSettings`)**: Modal providing model selection (`tiny`, `base`, `small`, `medium`), auto-detect vs manual language selection, beam size, and VAD toggle.
5. **Project Studio Integration**: Seamless tabbed sidebar alongside `JobQueue`, maintaining active playback synchronization and immediate response.

## 8. Test Verification & Benchmarks

The Phase 4 test suite (`backend/tests/test_phase4.py`) validates the full engine offline:
- **Speech Synthesis**: Integration tests utilize FFmpeg's built-in `flite` speech synthesizer to generate authentic spoken audio (`"ClipForge AI local speech test"`) without external network dependencies.
- **Model Download & Verification**: Verified on the `tiny` model (74.6 MB), passing file checksums and directory layout checks.
- **Inference Verification**: Transcribes synthesized speech in **2.38s** on the i7-13620H CPU, yielding exact word timestamps with 0.85+ confidence.
- **Segment Editing**: Updates segment text and confirms updated full-text synchronization.
- **Zero-Speech Handling**: Validates graceful handling of pure tone/silence audio.
- **Hardware Fallback**: Actively verifies that missing cuBLAS triggers safe CPU `int8` fallback without raising uncaught exceptions.
